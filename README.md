SmallCnn - ესაა პროექტში ყველაზე მარტივი cnn რომელიც 1 -> 32 32 -> 64 დროპაუთით და ბაჩ ნორმალიზაციით. მოდელი ანდერფიტში წავიდა და საუკეთესო შედეგად 0.56 დააბრუნა თუმცა ვცადე მოდელის ბევრი ვარიაცია. პირველ ჯერზე 
როცა დროპაუთი 0.25, 64 ბაჩსაიზი და 30 ეპოქა იყო კონფიგებში, მაშინ მიაღწია მოდელმა სწორედ 0.56 აკურატულობას ვალიდაციაზე. მერე დავიწყე ექსპერიმენტების ტარება და დროპაუთი გავზარდე 0.5, ბაჩსაიზი კი 128ზე. მივეცი უფრო 
მეტი ეპოქაც. მოდელმა პირველ ეპოქებზე ძალიან არასტაბილური შედეგები აჩვენა, მაგრამ 50ე ეპოქისთვის სწრაფად დაიწყო აქურესიმ ზრდა. ამიტომ მივეცი იგივე მოდელს მეორე შანსი და უფრო მეტი ეპოქა, აფდეითი ისევ ცვალებადი იყო 
მაგრამ მოდელმა ბევრ ეპოქაზე 0.54ს მიაღწია. საბოლოოდ 0.4 დროფაუთით და 80 ეპოქით მივაღწიე უკეთეს შედეგს და მოდელმა დააფიქსირა 0.569 აქურასი ვალიდაციაზე. სხვაობა თრეინისა და ვალიდაციის ქულებს შორის დიდი არ იყო, თუმცა
მოდელი აშკარად ანდერფიტში იყო და შესაბამისად ვერ აღწერდა დატასეტის სირთულეს. ამიტომ გადავედი შეწმდეგ არქიტექტურაზე. 

DeepCnn - აქ გამოვიყენე შემდეგი არქიტექტურა: Conv 3×3 → BatchNorm → ReLU Conv 3×3 → BatchNorm → ReLU maxpool ეს იყო ერთი ბლოკი და სულ მქონდა ასეთი 4 ბლოკი 1->64 -> 128 -> 256 -> 512 და შემდეგ ადაპტაციური ევერიჯ პულინგი. 
პირველივე გაშვებაზე 70 ეოიქაში, ბევრად უკეთესი შედეგი მაჩვენა ვიდრე წინა არქიტექტურამ. 0.67 ან 0.68 იყო ვალიდაციის ქულა. თუმცა იყო მცირედი ოვერფიტინგის ნიშნები. ამიტომ დავიწყე ექსპერიმენტების ტარება კონფიგურაციებზე. ჯერ ბლოკების განზომილებები
შევამცირე და 1 -> 32 -> 64 -> 128 -> 256ზე დავიყვანე, შემდეგ ისევ იგივეზე დავაბრუნე. გამოვიყენე გრადიენტ ქლიფინგიც და თავად დატასეტს შევუცვალე წონები, რადგან როგორც ზემოთ აღვნიშნე დატასეტი იყო კლასებად დაუბალანსებელი. დავიწყე learning rateის დინამიურად ცვლილებაც და adam ოპტიმიზაციიდან გადავედი adamwზეც რათა უკეთ დააფდეითებულიყო დიქეი.
გავაკეთე აუგმენტაციაც RandomAffine და RandomErasingით.
საბოლოოდ ოვერფიტის პრობლემა შედარებით გადაიჭრა და ნაკლებ ეპოქაში მივაღწიე, 0.67 ვალიდაციის ნიშნულს.

საშუალო შედეგი კი იყო 0.66. დავამატე labesmoothing და შევცვალე ლერნინგ რეიტის დინამიურად ცვლილების მეთოდი.
